# 새 전공 패키지 추가 가이드

이 문서는 「중등 임용 플래시카드」 앱에 새 전공(예: 체육 `pe`)의 콘텐츠를 만들어 넣는 방법을 정리한 것이다.
앱 코드는 손대지 않는다. 필요한 것은 **`subjects/<전공id>/` 폴더**와 **`exam/<전공id>/` 폴더**뿐이다.
미술(`art`)은 이미 완성된 참고 사례이므로 형식이 헷갈리면 `subjects/art/`와 `exam/art/`를 열어 보면 된다.

---

## 0. 전체 흐름 (한눈에)

1. 자료 확보: 기출 PDF(평가원 문제지 원본), 참고 교재·요약 자료를 `../<전공>전공/` 아래에 둔다. 예: `../체육전공/기출문제/*.pdf`
2. `subjects/pe/config.json` 작성
3. `subjects/pe/cards.csv` 작성 (핵심 작업, 1,500~2,000장 목표)
4. `subjects/pe/links.csv` 작성 (선택, 관계 그래프)
5. `subjects/pe/exams.json` 작성 → `python tools/extract_exam.py pe` → `exam/pe/` 에 문항 이미지·index.json 생성
6. 기출 문항 읽고 카드에 출처 태그 달기 + 없는 카드 만들기 + `exam/pe/answers/<시험id>.json` 참고 답안 작성
7. `python tools/upload_firestore.py pe` 로 Firestore 업로드, `git add exam/pe subjects/pe/config.json subjects/pe/exams.json` 커밋·푸시
8. `python tools/grant_major.py <이메일> pe` 로 사용자에게 전공 부여 → 앱에서 확인

`cards.csv`·`links.csv` 는 저장소에 올리지 않는다(.gitignore). Firestore에만 올라간다. 원본은 OneDrive 폴더에 있으므로 백업된다.

## 1. 폴더와 파일

```
flashcard/
  subjects/
    common/            공통 교육학 (건드리지 않음. 모든 전공에 자동으로 함께 실림)
    art/               미술 (참고 사례)
    pe/                ← 새로 만듦
      config.json      전공 메타
      cards.csv        카드 (Firestore 전용, git 제외)
      links.csv        관계 (Firestore 전용, git 제외)
      exams.json       기출 PDF 목록과 분할 설정
  exam/
    art/
    pe/                ← extract_exam.py 가 만듦 (git 에 올림)
      index.json
      2026A/q01.jpg …
      answers/2026A.json …
  tools/
    extract_exam.py    PDF → 문항 이미지
    exam_segments.py   문항 영역 자동 분할 (평가원 2단 조판 전용)
    upload_firestore.py
    grant_major.py
    reports.py         사용자 신고 검토
```

### config.json
```json
{
  "id": "pe",
  "kind": "major",
  "name": "체육",
  "title": "중등 임용 플래시카드",
  "examTotal": 80,
  "examLabel": "전공 (2·3교시)",
  "subjectAbbr": {"운동생리학": "생리", "운동역학": "역학", "스포츠심리학": "심리", "스포츠사회학": "사회", "체육교육학": "교육", "체육사·철학": "사철", "운동학습": "학습"}
}
```
- `subjectAbbr`: 약점 지도 칸에 쓰는 과목 약칭(4자 이내 권장). 과목명은 cards.csv 의 `과목` 컬럼 값과 정확히 일치해야 한다.
- `examTotal` 은 전공 배점(80). 교육학 20점은 common 이 맡는다.

## 2. 카드 CSV 스키마

머리글(순서 고정):
```
id,표제어,표제어변형,축1,축2,축3,축4,캡션,이미지링크,중요도,과목,유형,시대,태그,출처
```

| 컬럼 | 규칙 |
|---|---|
| id | 패키지 안에서 고유한 정수. **한 번 정하면 절대 바꾸지 않는다**(학습 기록의 키). 1부터 순번. |
| 표제어 | 카드의 답(용어·인물·작품명). 짧고 표준적인 표기. 같은 표제어 중복 금지. |
| 표제어변형 | 한자·영문·약어·별칭을 ` / `로 구분. 검색과 힌트에 쓰인다. |
| 축1 | **필수.** 정의·핵심 설명. "설명 제시" 모드에서 앞면에 나오므로 **표제어(답)나 그 일부를 포함하면 안 된다**(답 노출). 1~3문장, 100~200자. |
| 축2 | `예시: ...` 형식의 구체적 적용 사례 권장(성인 학습자에게 이해·기억 효과 큼). 뒷면에만 나온다. |
| 축3 | `의의: ...` / `비교: ...` / `배경: ...` / `관련: ...` 등 `라벨: 내용` 형식. 뒷면 전용. |
| 축4 | 필요 시 추가 축. |
| 캡션 | 작품·도판 카드의 "작가, 〈제목〉, 연도". |
| 이미지링크 | 공개 저작권(퍼블릭 도메인·CC) 이미지 URL. 위키미디어 `Special:FilePath/파일명?width=900` 형식 권장. 저작권 있는 현대 작품은 비움. |
| 중요도 | 1(최상)~4. 기준은 아래 참고. 앱 기본 필터는 1등급만 선택된 상태로 시작한다. |
| 과목 | 전공 하위 과목명(config 의 subjectAbbr 키와 일치). 한 카드 한 과목. |
| 유형 | `개념 / 기법 / 원리 / 인물 / 작품 / 사조` 중 하나. 체육이면 `개념 / 원리 / 인물 / 이론 / 기술 / 종목` 식으로 전공에 맞게 정해도 되지만 **6종 안팎**으로 유지. |
| 시대 | 미술사에서 쓰던 축. 시대성이 없는 전공이면 비워 둔다(약점 지도는 과목×유형만으로 묶인다). 값이 있으면 시대순 정렬용으로 일관된 표기. |
| 태그 | `;` 구분 다중값. 세부 주제 분류(예: `에너지대사;유산소`). 카드 목록 필터와 관련 항목(같은 갈래 형제) 계산에 쓰이므로 **한 카드 1~3개**, 전체 300~600종 이내. |
| 출처 | 기출 태그 `;` 구분. 형식 **`<시험id><문항번호>`** 예: `2026A5;2023B11`. 시험id 는 exams.json 의 키와 같아야 뷰어와 연결된다. |

쉼표가 있는 값은 `"..."`로 감싼다(UTF-8, BOM 없음, LF).

### 카드 작성 원칙 (미술 작업에서 굳어진 것)
- **앞면 답 노출 금지**: 축1에 표제어의 핵심 어절이 들어가면 안 된다. 작품 카드도 축1에 제목을 쓰지 말고 "○○이 그린 …" 식으로 우회.
- **한 카드 한 개념**: 여러 개념을 묶은 총론 카드보다 개별 개념 카드가 낫다. 다만 "○○의 4단계"처럼 세트로 외워야 하는 것은 세트 카드 하나 + 필요하면 각 단계 카드.
- **예시 축을 채운다**: 개념·원리·기법 카드는 축2에 구체적 적용 사례(수업 장면, 경기 상황, 실생활)를 쓴다. 정의만 있는 카드는 잘 안 외워진다.
- **비교 축**: 헷갈리는 짝(예: 정적 스트레칭/동적 스트레칭)은 축3에 `비교:`로 상대 개념과의 차이를 적는다.
- 문장은 평서형 명사 종결("~하는 것", "~이다" 생략 가능), 존댓말 없음, 이모지 없음.
- 인물 카드: 국적·시대·핵심 업적·대표 이론/저서를 축1에, 시험에 나오는 이론 이름은 별도 개념 카드로도 만든다.

### 중요도 배정 기준
- **1**: 기출에 직접 출제되었거나(빈칸 답·핵심 개념) 교육과정·주요 교재의 핵심 용어. 전체의 40~50%.
- **2**: 기출 지문에 등장하거나 1등급 개념을 이해하는 데 필요한 주변 개념. 30~35%.
- **3**: 심화·보조 개념. 15~20%.
- **4**: 참고 수준(있으면 좋은 상식). 5% 이내.
- 기출에 나온 것은 1로 올린다(태깅 단계에서 조정).

## 3. links.csv (선택)
```
출발,관계,도착,메모
최대산소섭취량,관련,유산소 능력,
```
- 표제어끼리 연결. 관계 종류: `관련`(대칭), `상위/하위`, `대비`, `영향`, `전후` 등 — 미술 파일 참고. 없는 표제어는 로더가 버리고 콘솔에 경고만 낸다.
- 같은 태그를 가진 카드는 이미 "형제"로 자동 연결되므로 links 는 태그로 표현되지 않는 관계만 넣으면 된다.

## 4. 기출문제 뷰어

### exams.json
```json
{
 "pdfDir": "체육전공/기출문제",
 "exams": {
  "2026A": {"title": "2026학년도 전공A", "pdf": "2026_체육_2a.pdf"},
  "2026B": {"title": "2026학년도 전공B", "pdf": "2026_체육_3b.pdf"}
 }
}
```
- 시험id 는 `연도+A/B`. 카드 출처 태그가 `2026A5`처럼 이 id 로 시작해야 카드 뒷면에서 문항 원문이 열린다.
- `python tools/extract_exam.py pe` 실행 후 출력의 **"N문항, 배점 합 40"** 을 확인한다. 문항 수가 끊기거나 합이 40이 아니면:
  - 배점만 못 읽은 경우: `"points": {"4": 4}` 로 보정
  - 텍스트가 깨지는 PDF(2025년 미술처럼 글꼴 매핑 오류): `"text": false`
  - 문항 분할이 어긋난 경우: PDF 블록 좌표를 보고 `"questions"` 에 수동 지정. 좌표 확인은
    `python -c "import pymupdf; p=pymupdf.open('...pdf')[0]; [print(round(b[0]),round(b[1]),round(b[2]),round(b[3]),b[4][:30]) for b in p.get_text('blocks')]"`
- 만든 이미지는 반드시 몇 장 눈으로 확인한다(다음 문항 머리글 침범, 전면 문항이 한 단만 잘림 등). 미술에서 발견된 오류 유형은 `exam_segments.py` 주석 참고.
- 2015 이전 형식(섹션별 번호 재시작)은 지원하지 않는다.

### 참고 답안 `exam/pe/answers/<시험id>.json`
```json
{
 "note": "한국교육과정평가원은 서술형 모범답안을 공개하지 않습니다. 아래는 학습용 참고 답안(비공식·자체 작성)이며 실제 채점 기준과 다를 수 있습니다.",
 "answers": {
  "1": ["㉠ 용어", "㉡ 용어"],
  "5": ["㉠ …", "㉡ …의 이유: …", "㉢ … 2가지: ① … ② …"]
 }
}
```
- 문항 하나 = 문자열 배열(한 줄에 하나의 소문항). 기입형은 용어만, 서술형은 채점 포인트가 되는 핵심어 중심으로 2~4문장.
- 확신이 낮은 항목은 문장 끝에 `※ …로 답할 수도 있음` 처럼 표시한다.
- 답안 문장에 카드 표제어가 그대로 들어가면 앱이 자동으로 링크를 건다. 그러므로 **답안의 용어 표기는 카드 표제어와 일치**시키는 것이 좋다.
- 도판만 있는 문항은 `exam/pe/<시험id>/qNN.jpg` 를 직접 보고 작성한다.

### 기출 태깅 절차
1. 문항 텍스트를 뽑아 읽는다(`extract_exam.py` 가 만든 index.json 의 `text` 는 첫 줄뿐이므로, 전문은 `page.get_text(clip=...)` 로 따로 뽑는다 — 미술 작업 때 쓴 방식: `auto_segments` 의 좌표로 clip).
2. 문항이 **직접 묻는 용어(빈칸 답)** 와 **도판·설명의 핵심 개념** 에 해당하는 카드에 `출처` 태그를 단다. 이름만 스치는 것은 제외.
3. 답인데 카드가 없는 용어는 **카드를 새로 만든다**(기출 = 1등급). 이 단계에서 카드가 100장 안팎 늘어나는 것이 정상이다.
4. 태그 형식 검증: `^\d{4}[AB]\d{1,2}$` 만 허용. 태그 수는 연도당 30~50개가 보통.

## 5. 업로드·배포·권한

```bash
python tools/upload_firestore.py pe          # Firestore bundle/pe/files 에 cards/links/config 업로드 (해시가 같으면 건너뜀)
git add subjects/pe/config.json subjects/pe/exams.json exam/pe && git commit && git push
python tools/grant_major.py                  # 사용자 목록·대기자 확인
python tools/grant_major.py user@x.com pe    # 전공 부여 (기존 전공 유지, 추가됨)
```
- 서비스 계정 키는 `../firebase-admin-key.json`(저장소 밖). 커밋 금지.
- 업로드 후 앱은 화면 복귀 시 새 버전을 감지해 자동 새로고침한다(최대 1분 간격 확인). 사용자가 전공이 둘 이상이면 설정 → 전공에서 전환.
- 보안 규칙은 새 전공을 추가해도 바꿀 필요가 없다(`users/{uid}.majors` 에 있는 id 면 자동 허용).

## 6. 품질 점검 체크리스트 (업로드 전)
- [ ] `id` 중복 없음, 정수, 빈 값 없음
- [ ] `표제어` 중복 없음
- [ ] `축1` 에 표제어(또는 핵심 어절)가 들어간 카드 없음 — 스크립트로 `표제어 in 축1` 검사
- [ ] `과목` 값이 config.subjectAbbr 키와 정확히 일치
- [ ] `유형` 6종 안팎, `중요도` 1~4 만
- [ ] 출처 태그 형식 검증, 시험id 가 exams.json 에 존재
- [ ] 이미지링크는 HEAD 요청으로 200 확인(위키미디어는 302→200)
- [ ] extract_exam 출력에서 시험지마다 "배점 합 40" 확인, 문항 이미지 무작위 5장 육안 확인
- [ ] answers/*.json 의 키가 index.json 의 문항 번호와 일치
- [ ] CSV 인코딩 UTF-8, 줄바꿈 LF

## 7. 새 세션 시작용 프롬프트 (복사해서 사용)

> `flashcard/docs/새_전공_추가_가이드.md` 를 먼저 읽고, 그 절차대로 **체육(pe)** 전공 패키지를 만들어라.
> 자료는 `../체육전공/` 아래에 있다(기출문제 PDF: `../체육전공/기출문제/`, 참고 자료: 그 옆 폴더). 큰 원본 하위 폴더는 열지 말 것.
> 순서: ① 자료 훑고 과목 체계·유형·태그 체계 초안을 나에게 보여 주고 확인받기 → ② config.json → ③ 기출 PDF 분할(exams.json → extract_exam.py, 배점 합 확인) → ④ 기출 문항 전문을 읽어 핵심 개념 목록 작성 → ⑤ cards.csv 작성(기출 개념 우선, 이어서 교재 핵심 개념; 앞면 답 노출 금지·예시 축 필수) → ⑥ 기출 태깅과 참고 답안 → ⑦ 체크리스트 점검 → ⑧ 업로드·커밋·전공 부여.
> 미술 패키지(`subjects/art`, `exam/art`)를 형식의 기준으로 삼되 내용은 참고하지 말 것. 앱 코드(app.js 등)는 수정하지 않는다. 각 단계가 끝나면 짧게 보고하고 다음으로 넘어가라.
